# 404 "Not Found" Page — Design

## Context

The portfolio site has no custom 404 page; Astro falls back to a generic
error. The user wants a custom "Not Found" page for this site now, and
intends to probably reuse the same page later as the default not-found
error page for other sites running on the same VPS (all of which are the
user's own projects, referenced from this portfolio).

## Scope

This spec covers only the portfolio site's 404 page
(`src/pages/404.astro`). Wiring a shared error page into the server config
for other sites is explicitly out of scope and will be a separate,
later effort.

## Decisions

- **Branding**: full "Simon Bouchard" branding is appropriate even for
  future reuse, since the other sites on the server are all the user's own
  projects — a lost visitor benefits from a clear way back to the
  portfolio regardless of which site they hit the 404 on.
- **Content**: minimal — a short message plus one link back to the
  portfolio home. No secondary nav links, no illustration.
- **Layout**: standalone and centered, not the site's full chrome
  (no sticky header/nav, no footer). This keeps the page self-contained,
  which matters because it may later be lifted out and reused as a static
  error page for other sites that don't share this site's routing or nav.

## Design

- **File**: `src/pages/404.astro`. Astro builds this to `dist/404.html`
  automatically, which is served for any unmatched route on this site once
  deployed. No dependency on `src/layouts/Base.astro` — the page defines
  its own full `<html>/<head>/<body>`, so it can be copied elsewhere later
  with nothing to strip out.
- **Content**:
  - "404" rendered in the site's mono font, like a status code.
  - A short line: "Page not found."
  - One link back to home, styled like the site's markdown links
    (`text-blueprint`, hover underline).
  - The home link is a **hardcoded absolute URL**,
    `https://simonbouchard.space/`, not a relative `/`. This is
    intentional: if this file is later reused as the default 404 for
    another site on the VPS, a relative link would point at that other
    site's domain instead of back to the portfolio.
- **Styling**: uses the same Tailwind theme tokens as the rest of the site
  (`ink`, `paper`, `graphite`, `blueprint`, IBM Plex Sans/Mono via
  `@theme` in `src/styles/tailwind.css`). Content is centered both
  vertically and horizontally in the viewport. No header, nav, or footer.
- **Head/meta**: `<meta name="robots" content="noindex, nofollow">` so
  the 404 isn't indexed, a plain `<title>404 — Simon Bouchard</title>`,
  standard charset/viewport meta, and the same favicon links used in
  `Base.astro`. Includes its own Google Fonts `<link>` tags (IBM Plex
  Sans/Mono) since it doesn't go through `Base.astro`.

## Testing

- `npm run build` produces `dist/404.html`.
- Visual check in the dev server at a nonexistent route (e.g.
  `/does-not-exist`), in both light and dark mode (the theme tokens are
  driven by `prefers-color-scheme`).

## Out of scope (noted for future work)

- Wiring this page (or a copy of it) into the VPS's web server config as
  the default 404 for other sites. That requires server-level changes
  outside this repo and will be scoped separately when it's actually
  tackled.
